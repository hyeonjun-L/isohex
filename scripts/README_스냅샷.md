# 점지 — 상가정보 분기 스냅샷 파이프라인

## 이게 푸는 문제

**(2026-10 정정) 상가업소번호는 재생성되지 않는다.** 2025Q4→2026Q1에 97.1%, 2026Q1→2026Q2에 90.2%가
같은 ID로 이어졌고, 이어진 쌍의 99.9%가 같은 업종·200m 이내였다. 그래서 **ID로 먼저 짝짓고**,
ID가 바뀐 것(재등록)만 아래 지문 단계로 넘긴다. 두 분기 ID가 절반도 안 겹치면 ID 단계를 건너뛴다.

| 단계 | 기준 | 흡수하는 것 |
|---|---|---|
| 0 | 상가업소번호 일치 | 대부분의 계속 영업 점포 |
| 1 | 지문(상호·업종·행정동) 일치, 다중집합 | ID만 바뀐 같은 가게 |
| 2 | 같은 상호·업종, 200m 이내 | 행정동 경계 근처 좌표 흔들림, 행정동 코드 변경, 근거리 이전 |
| 3 | 같은 업종, 30m 이내, 상호 접두 관계 또는 유사도 ≥ 0.75 | 상호 표기만 바뀐 같은 가게 (`워시엔조이` ↔ `워시엔조이양재점`) |

### 왜 이렇게 바꿨나 (2026-10-01, v2)

v1은 **좌표 3자리(≈110m) + 상호명 + 지점명**이었다. 두 가지 때문에 같은 가게가 '폐업 + 개업'으로 두 번 잡혔다.

1. **상가정보는 분기마다 좌표를 다시 계산한다.** 110m 칸 경계를 넘나들면 지문이 바뀐다 → 위치키를 행정동으로
2. **지점명 컬럼 채움률이 분기마다 흔들린다** (2022Q4 8.4% → 2023Q1 0.3% → 2026Q2 9.4%) → 지문에서 지점명을 뺐다

서울 2022Q4 → 2023Q1 실측:

| 지문 | 매칭률 | 개업 | 잔여오염* | 셀프빨래방 개업 |
|---|---|---|---|---|
| v1: 좌표3 + 상호·지점 | 67.1% | 115,616 | — | 321 |
| 행정동 + 상호·지점 + 200m | 70.7% | 96,686 | 39.3% | 300 |
| 행정동 + 상호만 + 200m | 76.9% | 63,291 | 15.5% | 16 |
| **+ 유사상호 30m (채택)** | **78.9%** | **52,834** | **1.1%** | **16** |

\* 잔여오염 = 남은 개업 중 같은 업종 폐업이 30m 안에 있고 상호 유사도 0.5 이상인 비율.
셀프빨래방(서울 871개)이 한 분기에 321개 '개업'하던 것이 16개로 내려왔다.

동일분기 지문 중복률은 1.1~1.5%로 늘지만 2% 게이트 안이다 (같은 동에 같은 상호의 지점이 둘인 경우).

`--fp-mode coord --coord-prec 3`으로 v1 방식을 재현할 수 있다 (비교용).

산출물 세 가지:

| 파일 | 내용 | 쓰임 |
|---|---|---|
| `poi_<분기>.parquet` | 점포 스냅샷 + H3 셀(res 8/9/10) | 피처 기반 |
| `change_<이전>_<현재>.parquet` | 개업·폐업 점포 | **라벨** |
| `grid<res>_industry_<분기>.parquet` | 격자×업종 점포수 | 집계 피처 |

## 설치

```bash
pip install h3 pyarrow pandas
```

## 사용

```bash
python ingest_sangga.py --raw data/raw --out data/snapshots --sido 서울 --res 8,9,10
```

- `--raw` 아래를 재귀 탐색해 `*상가(상권)정보*.csv`를 찾고, **파일명 끝 YYYYMM으로 분기를 인식**한다.
  월이 3·6·9·12가 아닌 파일(예: `_202510`)은 바로 앞 분기에 분기말 파일이 없으면 그 분기의 늦은 공개판으로 배정하고
  (`_202510` → 2025Q3, 콘솔에 `[배정]`), 있으면 겹치므로 건너뛴다
- 이미 적재된 분기는 건너뛴다 (재실행 안전)
- 직전 분기는 raw가 아니라 **출력 디렉터리의 기존 스냅샷**에서 찾는다. 분기가 하나씩 도착해도 diff가 돈다

## 원천 이상 — 적재 전에 알아둘 것 (2026-10-04, 서울 12분기에서 확인)

- **서울 2025Q1(`_202503`) 파일은 좌표 전체가 어파인으로 틀어져 있다.** 그대로 넣으면 서울 범위 밖으로 버려져
  "유효 레코드 0건"이 된다. 직전 분기 스냅샷이 있으면 공통 ID로 되돌린 뒤 적재한다:
  ```bash
  python scripts/fix_coords_affine.py <원본_서울_202503.csv> data/snapshots/poi_2024Q4.parquet <보정본.csv>
  ```
  서울 보정 잔차는 중앙 0.26m, 99% 1.11m였다. 다른 시도는 확인하지 않았다
- **분기 사이 변화에 원천 작업이 섞여 있다** — 2024-01~05 신규 접수 중단, 2024Q4 밀린 등록 일괄 반영(개업률 25.5%),
  2025Q3 옛 기록 재수록('개업'의 72%가 1년 넘은 ID), 2026Q2에 2025-06 이후 등록분 54~88% 철회.
  적재기는 그대로 담고, **라벨·생존 분석에서 ID 등록월로 거른다** (`analysis/panel/README.md`, 마스터플랜 §5.5)
- 상가업소번호 `MA` + 4자리 + **YYYYMM**(등록월). 첫 등장과 등록월의 시차가 3개월 이내면 새로 등록된 가게다
- 2025Q3·Q4 신규 등록분은 층 정보가 100% 공란이다
- macOS에서 받은 파일명은 NFD다. 적재기는 NFC로 정규화해 비교한다

## 품질 게이트

매 실행 후 `qc_report.csv`에 누적되고 콘솔에 판정이 찍힌다.

| 지표 | 기준 | 벗어나면 |
|---|---|---|
| 지문 중복률 | ≤ 2% | 층정보를 지문에 포함한다 |
| 직전 분기 매칭률 | ≥ 55% | 상호명 정규화·지문 위치키 재검토 |
| 총 점포수 변화율 | ±8% 이내 | 원본 수록범위 변경 의심 — 업종 대분류별 증감 확인 |
| 분기 개업률 | ≤ 6% | 원본 일괄 추가 의심 (ID 기준 2024Q4 25.5%, 2026Q2 10.6%). 이 구간 개업은 라벨로 바로 쓰지 말 것 — `analysis/panel`의 ID 등록월 규칙으로 거른다 |

기준치는 짐작이 아니라 서울 실측에서 잡았다. 좌표3 지문의 매칭률 상한이 약 70%이고,
2022Q4→2023Q1은 원본 수록범위 정비가 겹쳐 67.4%가 나왔다.

**서울 3개 분기 실측 (v2 지문)**

| 분기 | 점포수 | 좌표결측 | 지문중복 | 직전분기 매칭 | 개업 / 폐업 | 점포수 변화 |
|---|---|---|---|---|---|---|
| 2022Q4 | 534,283 | 0 | 1.44% | — | — | — |
| 2023Q1 | 474,250 | 0 | 1.07% | 78.9% | 52,834 / 112,867 | **-11.2%** |
| 2026Q2 | 554,083 | 0 | 1.45% | 67.7% (13분기 간격) | 232,944 / 153,111 | +16.8% |

2023Q1의 -11.2%는 실제 폐업이 아니라 **원본 수록범위 정비**다. 업종 대분류별로 보면
교육서비스업 -42.6%, 보건업 -60.0%가 대부분이고, 관심 업종인 독서실/스터디카페(-11%)와
셀프빨래방(-1.8%)은 전체 평균 수준이라 영향이 작다.

### 업종분류 개편 경계는 2022Q4보다 앞이다

2022Q4·2023Q1·2026Q2 모두 소분류 **246~247개**로 이미 개편 후 체계다.
따라서 2022Q4 이후 전 구간(15개 분기)을 업종코드 기준으로 이어 쓸 수 있다.
더 과거로 갈 수 있는지는 2022Q3 이전을 받아 `taxonomy` 열로 확인하면 된다.

## 과거 분기 확보 (수동, 1회)

공공데이터포털 [상가(상권)정보](https://www.data.go.kr/data/15083033/fileData.do) →
**"주기성 과거 데이터"** 탭에 2015Q4부터 43개 분기가 남아 있다. 로그인이 필요해 자동화는 안 되지만,
과거가 사라지지 않으므로 **서둘러 받을 이유도 없다.**

### 업종분류 개편 경계 (확인 완료)

상권업종 소분류가 **837 → 247**로 개편된 적이 있어, 개편 이전 파일에는
`R10202 독서실/스터디 카페`, `S20902 셀프 빨래방` 코드가 없다. 업종코드로 잡은 모집단 정의가
그 구간에서는 성립하지 않는다.

**2022Q4 시점에 이미 247체계임을 확인했다.** 따라서 2022Q4 이후는 안전하게 이어 쓸 수 있다.
더 과거가 필요하면 2022Q3 이전을 한 분기씩 받아 `qc_report.csv`의 `taxonomy` 열로 확인한다.

체계가 다른 두 분기가 인접하면 적재 시 경고가 찍히고 `qc_report.csv`에 `taxonomy_break`가 기록된다.
**그 구간을 걸치는 시점 분리 검증은 쓰면 안 된다.**

### 분기 스냅샷이 아닌 파일

과거 데이터 목록에는 `상가(상권)정보_의료기관_201909`, `전국 카페업소 수`, `전국 세탁소 현황(201711)`,
`수의업현황`, `포천시 업종별 업소수 변화추이` 같은 일회성 파일이 섞여 있다. 받지 말 것.
(받아도 스크립트가 건너뛴다.)

### 배치

받은 파일은 분기별 폴더로 풀어 `data/raw/` 아래 두면, 파일명의 YYYYMM으로 자동 인식된다.

```
data/raw/
  202403/..._서울_202403.csv
  202406/..._서울_202406.csv
  202606/..._서울_202606.csv
```

여러 분기를 한꺼번에 두고 한 번 실행하면 오래된 분기부터 순서대로 적재되고 diff도 연쇄로 만들어진다.

## 앞으로의 분기

갱신 주기는 분기, 차기 등록 예정일은 2026-10-31.
**별도 알림 작업은 두지 않았다** — 과거 분기가 전부 보존되므로 한두 분기 놓쳐도 나중에 받으면 된다.
분기가 바뀔 때 포털에서 받아 `data/raw/<YYYYMM>/`에 넣고 같은 명령을 다시 실행하면 된다.

## 알려진 한계

- **순증만 잡힌다.** 같은 격자에서 개업과 폐업이 상쇄되면 격자 집계로는 0으로 보인다. 점포 단위 `change` 파일을 쓰면 상쇄 전 값을 볼 수 있다
- **200m 넘는 이전(移轉)은 폐업+개업으로 잡힌다.** 200m 이내는 2단계에서 같은 가게로 묶는다
- **상호가 통째로 바뀌면 폐업+개업이 된다.** 표기만 바뀐 경우(접두 관계·유사도 0.75 이상)는 3단계에서 묶는다
- **같은 동의 같은 상호 지점끼리는 지문이 겹친다** (실측 중복률 1.1~1.5%). diff는 다중집합이라 개수는 보존되지만, 어느 지점이 닫았는지는 구분 못 한다
- **정상 분기 쌍의 ID 유지율은 95.8~97.4%다** (2025Q1→Q2, 2025Q3→Q4, 2025Q4→2026Q1). 2022Q4→2023Q1(수록범위 정비)은 83.3%, 2026Q1→Q2(철회·재수록)는 90.2%.
  12분기 전체 쌍의 품질표는 `analysis/panel/p1_pair_quality.py`
